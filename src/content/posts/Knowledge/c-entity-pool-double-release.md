## 背景と仕組み

固定長のEntityプールでは、空いている要素のインデックスを配列に並べ、`free_count` で有効範囲を管理できる。末尾から取り出せば後入れ先出しのスタック。先に入れた値から取り出すキューは先入れ先出しになる。

空き配列に同じIDを二度入れると、容量の範囲内でも同じEntityを二度払い出せてしまう。ここでいう二重返却は、プールの利用状態が壊れる現象。対策案は使用中フラグを持ち、使用中のIDだけを返却として受理すること。払い出しと返却の両方でフラグを更新する。古い参照が再利用後に残りうる設計では、世代番号も検討できる。

## 空き数とスロットの状態を照合する

`free_slots[0..free_count)` の各IDは範囲内で一意であり、使用中のスロットを含まない。これを払い出しと返却の両方が守れば、同じスロットを同時に2つの用途へ貸し出さずに済む。次は単一スレッドで返却を検査する説明例。

```c
bool release(Pool *pool, size_t id) {
    if (id >= CAPACITY || !pool->active[id]) {
        return false;
    }
    pool->active[id] = false;
    pool->free_slots[pool->free_count++] = id;
    return true;
}
```

世代番号を使う場合は、呼び出し側のハンドルにIDと世代を持たせる。返却して同じIDを再利用した後は、前の世代のハンドルを拒める。使用中フラグだけだと、再利用済みのIDを指す古いハンドルを区別できない。

## 環境と確認状況

C、SDLを使うEntityプール。C規格・コンパイラ・SDLの版は未確認。

現在のUFOゲームの `missile.c` では、返却関数は稼働フラグを落としてIDを積む。呼び出し元は稼働中のスロットを処理し、返却した分岐でその処理を終える。返却関数自体で重複を拒否するコードは上の説明例。Apple Clang 21.0.0でC17としてコンパイルした説明例を実行し、同じIDの2回目の返却で空き数が増えないことを確認した。
