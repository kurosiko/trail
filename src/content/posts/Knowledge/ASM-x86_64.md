ARM64の観察に続き、Apple SiliconのMacでmacOS向けx86-64プログラムをビルドし、Rosetta 2で実行した。引数の受け渡し方はx86-64向けのABIに従う。逆アセンブル結果はコンパイラやビルド条件で変わる。

```c
#include <stdio.h>

// 引数が 8 個ある関数
int add_all(int a, int b, int c, int d, int e, int f, int g, int h) {
    int sum = a + b + c + d + e + f + g + h;
    return sum; // ここにブレークポイントを置く
}

int main(void) {
    int result = add_all(1, 2, 3, 4, 5, 6, 7, 8);
    printf("Result: %d\n", result);
    return 0;
}
```

このコードを最適化無視して、デバッグ情報を付与しつつx86_64向けにコンパイル
掲載したLLDBの出力はAT&T記法。例えば `movq %rsp, %rbp` はコピー元、コピー先の順に並ぶ。表示記法はデバッガ側で選べる。
```console
$ clang -g -O0 -arch x86_64 demo.c -o demo
$ lldb demo

(lldb) b add_all
(lldb) r
(lldb) disassemble
```

## レジスタ引数とスタック引数の見分け方

この例はmacOSのx86-64向けに、最適化を外して生成したコード。`call` の直後は `rsp` が戻りアドレスを指す。`pushq %rbp` で呼び出し元のフレームポインタを保存し、`movq %rsp, %rbp` で現在のフレームの基準を作る。

```text
rbp + 24    第8引数 h
rbp + 16    第7引数 g
rbp +  8    戻りアドレス
rbp +  0    保存した呼び出し元の rbp
rbp -  4    第1引数 a の退避先
```

このダンプでは、第1〜6引数は整数引数用レジスタから負のオフセットへ退避される。一方、第7・8引数は正のオフセットから読む。このダンプは `rsp` を追加で引かず、フレームの下側を一時領域として使う。System V系のx86-64 ABIでは、このような葉関数は `rsp` より下にあるred zoneを使える。最後に結果を `eax` に置いて戻る。最適化を有効にすると退避やフレームポインタが省略されることがあるため、負のオフセットへの退避は観察したコードの特徴として読む。
